# SafeRide Nepal — Android / Team Setup Guide

This is the **only** setup guide team members need to connect an Android phone
to the SafeRide native stack. It supersedes any older Docker-era instructions.

> If something here disagrees with the laptop admin, the laptop admin is
> authoritative — they run the live stack and hold the secrets.

---

## 1. Architecture (what you are joining)

```
                 SAFE RIDE NEPAL — NATIVE STACK

        ┌──────────────────────────┐
        │       ANDROID PHONE      │   Termux + simulate_tap.py
        │  Front Camera (mirrored) │   or web Bus Scanner UI
        └──────────┬───────────────┘
                   │  HTTP :3000
                   ▼
        ┌──────────────────────────┐
        │      NESTJS BACKEND      │   /face/identify, /face-token
        └──────────┬───────────────┘
                   ▼
        ┌──────────────────────────┐
        │    FACE SERVICE :5001    │   reference images, matching, confidence
        └──────────┬───────────────┘
                   ▼
        ┌──────────────────────────┐
        │   MQTT :8883 (TLS) or    │   HMAC-signed attendance events
        │           :1883 (plain)  │
        └──────────┬───────────────┘
                   ▼
        ┌──────────────────────────┐
        │       POSTGRESQL         │   AttendanceEvent, Device, Student
        └──────────┬───────────────┘
                   │  Socket.IO
                   ▼
        ┌──────────────────────────┐
        │       DASHBOARD :5173    │   students, enrollment, live feed
        └──────────────────────────┘
```

Key rule: **HTTP API and MQTT broker are two different channels on the laptop.**

| Channel | Address |
|---|---|
| Backend API (HTTP) | `http://LAPTOP_IP:3000` — **no `/api` prefix** |
| Dashboard (HTTP) | `http://LAPTOP_IP:5173` |
| Bus Scanner web UI | `http://LAPTOP_IP:8100/scanner` |
| MQTT broker (TLS) | `LAPTOP_IP:8883` (default, needs `ca.crt`) |
| MQTT broker (plain) | `LAPTOP_IP:1883` (LAN fallback) |

---

## 2. What you need

- A laptop running the native stack (see §7). Ask the laptop admin for the
  laptop's LAN IP (e.g. `192.168.1.90`).
- An Android phone with **Termux** installed (F-Droid build recommended).
- The phone on the **same Wi-Fi network** as the laptop.

---

## 3. Phone setup (one-time, ~5 minutes)

Open Termux and run:

```bash
pkg update -y
pkg install -y git python termux-api curl
git clone https://github.com/Purushottamzha/hardware.git
cd hardware/simulator
bash setup_phone.sh
```

The script will:

1. Install Python packages (`paho-mqtt`, `requests` only).
2. Ask for the **laptop LAN IP** and check `http://LAPTOP_IP:3000/health`
   before doing anything else (aborts early with a clear message if the
   backend is unreachable).
3. Ask for a **unique device ID** (e.g. `bus-ba2kha4521-door-PHONE-TEAM1`),
   a **bus ID**, and admin login credentials.
4. Register the device with the backend via `/devices/register`.
5. Generate `simulator/config.json` with the returned device secret.
6. Ask whether to use MQTT **8883 TLS** (default, recommended) or **1883 plain**.

> Two phones must NEVER share the same device ID / secret / counter.

### What happens to the device secret

The secret is generated by the backend and written **only** into the phone's
local `simulator/config.json`. It is never printed in full, never committed,
and must not be shared in chat. `config.json` is gitignored.

---

## 4. One admin step on the laptop (MQTT credential)

The MQTT broker requires a credential per device. After the phone registers,
the **laptop admin** must run:

```bat
"C:\Program Files\Mosquitto\mosquitto_passwd.exe" -b C:\ProgramData\saferide-mosquitto\passwd <deviceId> <deviceSecret>
```

(deviceSecret is in the phone's `simulator/config.json` — have the phone owner
read it out on a trusted channel), then restart the LAN broker:

```bat
mosquitto -c C:\ProgramData\saferide-mosquitto\mosquitto.lan.conf
```

---

## 5. TLS (8883) — public CA certificate only

If you chose TLS, the phone needs the **public** CA certificate from the
laptop:

- On the laptop: `C:\ProgramData\saferide-mosquitto\ca.crt`
- Copy it to the phone (file manager, ADB, etc.), e.g. `/sdcard/Download/ca.crt`
- In `setup_phone.sh` enter that path when asked.

**Never** copy private keys (`ca.key`, `server.key`) — only the public
`ca.crt`. Never disable certificate verification.

---

## 6. Verify and run

On the phone, from `hardware/simulator`:

```bash
python simulate_tap.py --check     # backend / MQTT / CA / camera / config
python simulate_tap.py             # full tap: camera → identify → attendance
python simulate_tap.py --face-photo /sdcard/DCIM/student.jpg   # with a saved photo
```

`--check` is read-only (no MQTT publish, no DB writes). All lines should show
`OK` / `PASSED` before a real tap.

### Alternative: web Bus Scanner (no Termux camera needed)

Open `http://LAPTOP_IP:8100/scanner` in Chrome on the phone. It uses the
**front camera with a mirrored preview** and a face guide. On the phone,
one-time fix: `chrome://flags` → "Insecure origins treated as secure" →
add `http://LAPTOP_IP:8100` → Relaunch.

## 7. Laptop admin — native stack startup (for reference)

| # | Service | Command |
|---|---|---|
| 1 | PostgreSQL | running Windows service |
| 2 | Mosquitto LAN broker (0.0.0.0:1883 + 8883 TLS) | `mosquitto -c C:\ProgramData\saferide-mosquitto\mosquitto.lan.conf` |
| 3 | face-service | `ops\start-face-service.bat` (port 5001) |
| 4 | Backend (0.0.0.0:3000, LAN MQTT) | `ops\start-backend-native.bat` |
| 5 | Dashboard | `ops\start-dashboard.bat` (port 5173) |
| 6 | Scanner bridge | `scanner-bridge\run_bridge.bat` (port 8100) |

Verify: `http://192.168.1.90:3000/health` → `{"status":"ok","mqtt":"connected","faceService":"online"}`.

## 8. Troubleshooting

| Symptom | Fix |
|---|---|
| `--check` fails on API | Phone and laptop on same Wi-Fi; laptop profile **Private**; firewall allows 3000 |
| MQTT connect refused | LAN broker not running; `netstat -ano \| findstr :1883` must show `0.0.0.0:1883 LISTENING` |
| MQTT auth error (TLS) | Admin hasn't added the device credential (§4); or wrong `ca.crt` |
| No dashboard events | Backend must subscribe on the LAN broker (`MOSQUITTO_HOST=192.168.1.90`), not loopback |
| Camera blocked in Chrome | Grant permission; apply the `chrome://flags` workaround for the scanner URL |
| "counter too old" rejection | Phone's local `counter` must exceed the backend's `lastSeenCounter` for that device |
| Login fails (lockout) | 5 failed attempts lock the account for 15 min — wait, or ask the admin |

---

## 9. Do NOT do these

- Do not commit `simulator/config.json`, `ops/native.env`, `backend/.env`,
  `mosquitto/certs/`, `backend/uploads/`, `*.log`, or `phone-package/`.
- Do not copy `.env` / secrets / TLS private keys between team members.
- Do not push secrets to GitHub. Tracked example configs contain only
  placeholders.
- Do not rewrite `simulate_tap.py` or the backend unless a real failure is
  found — the pipeline (identify → face-token → HMAC → MQTT QoS1 →
  attendance) is verified and frozen.
